# security/ —— 标识外流的出口拦截

政策见 `docs/SECURITY.md` §6；设计与理由见
`内部设计记录`。
**本文件只讲怎么做。**

## 它拦什么

四种形状：`wxid_[A-Za-z0-9_-]{4,}`、`[0-9]{6,}@chatroom`、`1[3-9][0-9]{9}`、
`/Users/<第一段>`（第一段不是 `you`、也不是 `Shared`）。

最后一种守的是 CONTRIBUTING §4 那条「本机绝对路径不得入库」。三条要知道的：

- 它命中的是**第一段**（用户名），不是整条路径——所以指纹与路径后面的内容无关。
- 它**永不登记**：`--allow` 会直接拒绝；**手抄一行进清单也不生效**——豁免清单对路径形
  整体失效，那一行还会被 `--verify-allowlist` 判成死条目（`--values` 里这种值显示
  「不可登记」）。登记它等于把真实用户名写进一个会被提交的文件，而 §4.3 的不变式 1
  **查不出来**（那个值仍在原文里命中，不算死条目）。两条正解：**改写那处文字**，占位符
  一律用 `/Users/you`；文档或测试夹具确实需要出现这个形态时，用**字符串拼接**
  （`"/Users/" + "somebody"`）让源码里不存在完整字面量——本仓 `tests/test_scan.py`
  就是这么做的。
- 两个例外**按 (文件, 形状)** 写在代码里（`PATH_EXEMPT_FILES`）：`.mcp.json` 与
  `.codex/config.toml`——它们是 §4 的功能性本机配置，写的就是真实路径。
  **只豁免路径形**，其余三种形状在这两个文件里照扫。

⚠️ 手机号那支**只在仓库内使用**。仓库外（`/tmp`、`~/.claude`、`~/.codex`）的复查只用前
两种形状——实测手机号在 `/private/tmp` 单目录就有 1000 个以上假阳性（别的项目构建树里的
UUID 段与数字常量），误报比到 10³:6，人眼看不见信号。
**路径形也不进仓库外复查**：量级比手机号还大——实测 `~/.claude` 一个目录就有 **15,675 个
文件**命中该形态（2026-10-12；口径 `/Users/` 后接一段非 `you` 的成分），那三个目录里到处
是工具输出引用本机路径。
命中且**不在** `allowlist.txt` 里 → 拦下。

**它扫不到**：自定义微信号、群名、备注名、聊天正文片段、导出产物。
形状扫描有原理边界——能枚举的只有形状。
路径形另有**三条已知漏面**（刻意留的，不是没想到）：**非 ASCII 用户名**（字符集是 ASCII）、
**小写的 `/users/…`**（不做大小写折叠——折叠会拿 `/users/<id>` 这类 URL 片段换假阳性，
而本形状没有豁免清单这条退路）、只认 **macOS 的 `/Users/`**（`/home/…` 与 `C:\Users\…`
不拦——别的平台的同性质路径不在形状里）。

⚠️ **二进制 / 非 UTF-8 文件根本没有被检查**——这是与上面**不同**的一条边界：
`--all` 读不出 UTF-8 就整份跳过；`--staged` 对二进制文件一行都不扫（git 不为二进制给新增行），
只在 stderr 点名警告一句（「X 是二进制文件——它一行都没被检查」），**退出码不变**。
上面那句说的是「读了也未必看得懂」，这句说的是**压根没读**——别把它读成「二进制也扫过、干净」。

生成的依赖锁（`uv.lock`）**整份跳过**（`--all` 与 `--staged` 同一条规则）：里面是第三方包
元数据，实测单独贡献 47 处手机号形假阳性。

## 装钩子（每个 clone 都要装一次）

钩子**不入库**，所以换机器 / 换 clone 必须重装。**装到共享 hooks 目录**——
`git rev-parse --git-common-dir` 下的 `hooks/`。主检出与它的所有 worktree 共用同一个，
所以在哪个里装效果一样；而直接写 `.git/hooks/` 在 worktree 里会**失败**：worktree 的
`.git` 是一个**文件**，不是目录。

**在你想保护的那个检出里跑**。（若本计划是在 worktree 中执行的，安装与下面的三个探针
验收留到合回 main 之后从主检出做。）

```bash
H=$(cd "$(git rev-parse --git-common-dir)" && pwd)/hooks
mkdir -p "$H"

cat > "$H/pre-commit" <<'SH'
#!/bin/sh
# 标识外流拦截：扫暂存区新增行。装法与理由见 security/README.md。
set -u
root=$(git rev-parse --show-toplevel) || exit 1
for py in "$root/.venv/bin/python3" /usr/bin/python3; do
    [ -x "$py" ] && exec "$py" "$root/security/scan.py" --staged
done
echo "scan: 找不到可用的 Python 解释器（试过 .venv/bin/python3 与 /usr/bin/python3）" >&2
exit 2
SH

cat > "$H/commit-msg" <<'SH'
#!/bin/sh
# 标识外流拦截：扫提交信息。**2026-09-27 那次真标识就躺在提交信息里。**
set -u
root=$(git rev-parse --show-toplevel) || exit 1
for py in "$root/.venv/bin/python3" /usr/bin/python3; do
    if [ -x "$py" ]; then
        "$py" "$root/security/scan.py" --text "$1" || exit $?
        exit 0
    fi
done
echo "scan: 找不到可用的 Python 解释器（试过 .venv/bin/python3 与 /usr/bin/python3）" >&2
exit 2
SH

chmod +x "$H/pre-commit" "$H/commit-msg"
```

**`chmod +x` 不能省。** 没有执行位时 git 会**跳过**钩子——它**不会失败**、照常提交，
照常提交。这是本机制最隐蔽的失效方式。

## 退出码

| 码 | 含义 |
|---|---|
| `0` | 干净 |
| `1` | 命中（**拦截**）——**逐入口的含义不同**，见下表 |
| `2` | **扫描器自身出错**（找不到 git / 解释器 / 提交信息不是 UTF-8 / 豁免清单读不了）**或按政策拒绝执行**（`--allow` 撞上**不可登记**的形状，今天只有路径形）——同样拦截 |

`2` 也拦，这是刻意的：**fail-closed**。放行等于「装了但从未生效」。

**`1` 在三个入口上不是同一件事**（本机实测 2026-10-12；一律是拦截，但**不是每一处 `1`
都等于「发现泄漏」**）：

| 入口 | `0` | `1` |
|---|---|---|
| `--all` / `--staged` / `--text` | 没有**未登记**的命中 | 有未登记的命中 |
| `--values` | **一条命中都没有** | **只要有命中就退 1**，不论登记与否——本仓库实测 50 条**全部已登记**、未登记 0 条，仍退 1 |
| `--verify-allowlist` | 无死条目 | 有**死条目**（清单里在仓库一次都没命中的项） |

`2` 对三者同义，且**有两类成因**：一是扫描器自身出错（上面那行括号里的几样），二是
**按政策拒绝执行**——今天只有一处：`--allow` 撞上不可登记的形状（路径形；见上）。
第二类也归 2，因为它同样不是「干净」：**放行等于装了个不生效的东西**——退出 0 会让
操作者以为「登记好了」，而那次登记根本没发生（清单的规矩是「只许放假值」，而路径形的值
只能是真路径），钩子下一次照样拦。

后两行的 `1` 都不是「发现泄漏」——`--values` 判的是「汇总表非空」（它是逐值视图的出口，
不是门禁），`--verify-allowlist` 判的是清单里的死条目（设计的 §4.3 不变式 1）。别把这两条
`1` 读成「仓库里有未登记的标识」。`--values` 的 `state` 列有三种取值：`已登记` / `未登记` /
**`不可登记`**（路径形——清单对它整体失效，显示成前两种都是假话）。

## 环境注意

- 钩子在**你的登录 shell** 里跑；git 可能是 GitHub Desktop 自带的 stripped 版。
  解释器按 `.venv/bin/python3` → `/usr/bin/python3` 依次找，都找不到就退出 2。
- GitHub Desktop **3.5.5 起**会执行 `pre-commit` 与 `commit-msg`（本机 3.6.6 ✓）。
  它**不拦截 `pre-push`**——不要依赖 pre-push 兜底。
- 逃生门是 `git commit --no-verify`。**用它之前先想清楚**。

## 加一条豁免

**不要手抄值**（手抄意味着你先把值读了出来）：

```bash
uv run python security/scan.py --values            # 找到 #指纹
uv run python security/scan.py --allow <指纹>      # 按指纹登记，全程不打印值
uv run python security/scan.py --verify-allowlist  # 确认没有死条目
```

`allowlist.txt` 里**只许放假值**。对**可登记**的三种形状，这一条没有任何自动化能替你守——
「拿清单里的值去真实数据里查」这类 oracle 是**必要不充分**的（群解散了就查不出来）。
（路径形不在此列：它连手抄都不生效，见上。）

## 定期复查（仓库外那一层）

扫描器**只管仓库内**。仓库外靠手工：

```bash
grep -rlIE 'wxid_[A-Za-z0-9_-]{4,}|[0-9]{6,}@chatroom' ~/.claude ~/.codex
```

（**刻意不含手机号那一支**：实测它在 `/private/tmp` 单目录就有 1000 个以上假阳性，落在别的
项目构建树的 UUID 段与数字常量中间；同一版本在 `~/.claude/plugins` 下 wxid/chatroom
形状为 **0**、命中**全部**是手机号夹具。误报比到 10³:6，人眼看不见信号。）

**只看命中的顶层位置有没有落在 `docs/SECURITY.md` §4 那个清单之外，不要照抄输出**——
实测它会列出上千条路径，而且会把第三方插件里手机号形状的夹具算进来。
