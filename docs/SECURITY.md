# SECURITY — 隐私与安全

> 本文档说明项目处理了哪些敏感数据、如何保护它们，以及你必须了解的法律与平台条款
> 风险。**使用前请完整阅读本文档。**

## 1. 项目处理了什么数据

| 数据 | 位置 | 敏感度 |
|---|---|---|
| 数据库密钥 passphrase（32 字节） | 内存（微信进程）→ `~/.agent-wechat/passphrase.json` | 极高 |
| 聊天数据库（加密） | 微信容器目录 | 高（本工具不解密落盘存储它） |
| 解密后的消息明文 | `~/.agent-wechat/tmp/`（临时）→ `index.db`（持久） | 极高 |
| 解密后的媒体明文（图片/语音 WAV/视频） | `~/.agent-wechat/media/`（持久） | 极高 |
| 朋友圈正文 / 评论 / 点赞 / 媒体明文（`moments export` 产物） | `~/.agent-wechat/moments/`（持久；目录 0700、文件 0600） | 极高 |
| **例外**：`moments export --out DIR` 会把同一份朋友圈明文（含已下载的媒体）写到**任意指定目录** | `DIR`（代码尽力 chmod 0700，但不在 `~/.agent-wechat/` 之下） | 极高（用后必须手动删除；不受 Time Machine 排除与 `purge` 覆盖） |
| **例外**：`decrypt <db> --out` 调试命令会**持久**写出整库明文 | `~/.agent-wechat/<out>` | 极高（用后必须手动删除） |
| **例外**：`media export --out DIR` 会把同一份媒体明文写到**任意指定目录** | `DIR`（代码尽力 chmod 0700，但不在 `~/.agent-wechat/` 之下） | 极高（用后必须手动删除；不受 Time Machine 排除与 `purge` 覆盖） |

数据流向**默认始终在本机**：embedding、检索、MCP（stdio 传输）全部本地闭环，
不存在任何网络上传路径。媒体导出同理——pilk（进程内调用）与 ffmpeg（本地子进程）
都只做本机解码，不联网、不上传。

### 零网络例外（仅朋友圈媒体下载）

上面那句「不存在任何网络**上传**路径」在本例外下**依然成立**——这里被打破的是「零网络」，
不是「零上传」：流量是**入站方向**的（只从微信 CDN **取**媒体本体），本机不向任何服务器
发送聊天 / 索引 / 密钥内容。这个例外具体是什么：

- **触发条件**：只有用户显式指定 `--with-media`（CLI `moments export`）或
  `with_media=True`（MCP `export_moments`）时才成立。两者默认都是 `False`
  ——不加则整次导出一个网络请求都不发。
- **目标域**：只连微信 CDN 的 `*.qpic.cn` 与 `*.video.qq.com`（代码里是后缀白名单，
  跨重定向也成立）；其余主机一律拒绝，请求不会被引向别处。
- **发送内容**：请求只携带微信自己签发的媒体 `token` 与固定 `User-Agent`
  （`MicroMessenger Client`），**不含本机任何聊天 / 索引 / 密钥内容**，无请求体。
- **不走代理**：一律直连，不读 `http_proxy` 等环境变量。
- **目录只读**：产物只写 `~/.agent-wechat/moments/`（或用户显式 `--out`），
  绝不写回微信目录。

## 2. 密钥如何获取（风险最集中的环节）

`bootstrap` 的原理：对微信 ad-hoc 重签名去掉 Hardened Runtime → lldb attach 微信进程
→ 在系统函数 `CCKeyDerivationPBKDF` 上下断点 → 用户在微信内重新登录触发密钥派生 →
从寄存器读取 32 字节 passphrase → HMAC 校验通过后落缓存。

**风险与性质**：

- lldb 仅在断点命中的瞬间读取一次寄存器即 detach；不修改微信行为、不接触网络协议、
  不注入代码。公开同类工具（跨平台、经大量真机验证）均采取同一原理且未报告触发风控，
  但**无官方保证**，理论上存在账号受限风险
- 重签名会修改 `/Applications/WeChat.app` 的代码签名（数据不受影响）；微信每次升级
  会还原签名，需重跑
- passphrase 缓存文件 `0600` 权限，仅当前用户可读；它**不会**被写入日志或错误信息

**替代方案（未采用，供了解）**：关闭 SIP 可绕过重签名，但影响整机安全面，代价远大于
收益；纯文件解析路线已通过 HMAC 验证系统排除（见 ARCHITECTURE.md §3.2）。

## 3. 只读保证与账号隔离

- **只读**：代码不存在对微信容器目录的写路径；解密用 db+wal+shm **快照**进行，
  即使微信正在写入也不受影响
- **账号隔离**：数据目录按 `wxid` 物理隔离；passphrase 按账号分键；读取/导出默认
  操作**当前登录账号**，可用 `--account` 显式指定本机已有账号。**技术上无法访问
  未在本机登录过的他人账号数据**（没有其密钥）
- **权限边界**：不使用辅助功能权限；不需要关闭 SIP；MCP 走 stdio，不监听任何网络端口

## 4. 明文数据的存储与访问控制

全量导出会在 `~/.agent-wechat/index.db` 形成**一份完整的、可检索的明文聊天档案**——
这是本项目最大的数据资产，也是最大的风险面。已落实的控制：

| 控制项 | 措施 |
|---|---|
| 文件权限 | `~/.agent-wechat/` 全目录 `0700`，passphrase 缓存 `0600`（仅当前用户可读） |
| 全盘加密 | 索引明文依赖 **FileVault**（安装前提，见 INSTALL.md）；未开 FileVault 的机器不应使用本项目的导出功能 |
| 备份排除 | 首次使用时代码自动执行 `tmutil addexclusion ~/.agent-wechat`（可用 `tmutil isexcluded` 验证）；失败时请手动执行，防止明文档案绕过 FileVault 进入备份盘 |
| 临时文件 | 解密明文仅在 `tmp/`（0700）短暂存在，单分片、用后即焚；唯一例外是 `decrypt --out` 显式导出的明文库（见上表） |
| 传输 | MCP 走 stdio；无网络监听、无云同步路径 |
| 销毁 | `agent-wechat purge --all --yes` 一键清除全部敏感数据（密钥 + 索引）；不加 `--yes` 只预览，删完给出残留核查。手工 `rm -rf ~/.agent-wechat` 仍是等价后备 |

**用户侧建议**：

- 不要把 `~/.agent-wechat/` 移入 iCloud/Dropbox 等同步目录
- 蒸馏产物（JSONL 等）同样敏感，用完即删，不要进入任何同步/共享路径
- 不在聊天内容中出现的场合（屏幕共享、演示）运行 `recent`/`search`

## 5. 法律与平台条款风险（请务必知悉）

- **平台条款**：解密本地数据库、读取进程内存大概率违反《微信软件许可及服务协议》
  的相关条款
- **执法先例**：2025-10-20，同类开源项目 sjzar/chatlog 作者收到微信官方函件后
  删除全部代码；更早的 Memotrace、wechatbackup 遭遇相同命运。被发函的直接触发因素是
  **公开仓库分发**——个人自用与公开发布的风险量级不同，但"规避技术保护措施"的
  法律定性本身存在争议，**风险不为零**
- **本项目的边界**（也是对使用者的要求）：
  1. 仅处理**本机本人已登录**账号的数据；不得用于获取他人数据
  2. 仅本地使用：**不公开分发代码、不打包传播、不撰写公开教程**
  3. 导出数据不对外提供，不接入任何外部服务
